# Codex ルール

Claude Code と Codex は入口ファイルが違う（`CLAUDE.md` / `AGENTS.md`）が、**ルール本文の正本は `.claude/rules/` の 1 箇所**である。本ファイルは Codex 側の運用差分だけを定める。

- **AGENTS.md の階層適用**: リポジトリ直下から変更対象までのすべての祖先ディレクトリにある `AGENTS.md` を読み、指示を合わせて守る。ルール本文を `AGENTS.md` へ複製しない。
- **適用範囲を絞らない**: 本プロジェクトは `.claude/rules/` の**全ルールをスコープに関わらず常に適用する**（`CLAUDE.md`「Rules」）。各ルールの `globs` は「主にどの領域の話か」を示す索引であり、読まなくてよい理由にはならない。
- **Claude 固有機能の読み替え**: `CLAUDE.md`・`shortcuts.md`・`.claude/skills/` で Claude Code 固有の機能やスキル名が指定されている場合は、利用可能な Codex の機能・指示へ**意図を保って**読み替える。読み替えられない場合は、作業を進める前にユーザーへ確認する。
- **ルールの同期**: `.claude/rules/` のファイル追加・削除・改名・適用範囲変更時は、`CLAUDE.md`・`AGENTS.md`・README の AI エージェント向け記述を**同じ変更セットで**同期する。ルール本文だけの変更では入口ファイルの更新は不要。

## GitHub 操作

- **PR の承認・マージを実行しない**（`git.md`「PR の承認・マージは必ず人間が行う」）。
- ユーザーが承認・マージを完了した後は、**PR のマージ状態を確認してから**、main の最新化・マージ済みブランチの削除といったローカル後処理だけを行う（`shortcuts.md`「PR承認しました」）。

## 破壊的操作

Codex も**エージェントとしての制約は Claude Code と同じ**であり、`production-data.md`「AI エージェント（Claude Code / Codex / MCP）に対する制約」がそのまま適用される。特に以下を守る。

- 本番プロジェクトに対する書き込み系操作を実行しない。参照系に留める。
- **エラーの回避策として接続先を変更しない**（「ローカル DB に繋がらないから本番を使う」「環境変数を手で書き換えて通す」は禁止）。原因を報告して止まる。
- テストの接続先は `TEST_DATABASE_URL` のみを参照する（`testing.md`「テスト用 DB の接続先」）。
